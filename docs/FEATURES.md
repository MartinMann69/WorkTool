# Current features

- **Explorer row actions:** Applications and Documentation rows include a folder-icon button with an Open in Explorer tooltip. Applications resolve the executable/shortcut on the current PC and select that file without launching it or passing launch arguments. Documentation folders open directly in Explorer; documentation files are selected in their containing folder. Missing targets report an error.
- **File and folder documentation connections:** every documentation row offers a chain button and Connections menu action, including ordinary files and browsed folders. Connect an app/license from either side. Non-documentation entry pickers separate Documentation into its own lazy-loaded, searchable folder tree with independent file/folder checkboxes; documentation's own picker keeps the regular entry list. Draft references are published only with the owner Save. File links open the actual file, folder links open the browser, and moves preserve IDs. Catalog format 3 adds the documentation kind; upgrades retain folder IDs/links and keep an exact original backup. Upgrade both admin PCs to 0.7.0 before sharing the upgraded catalog.
- **Stable documentation status:** loading and file-operation messages appear beside the folder/file count in a fixed-height footer. Long messages are shortened visually and available in full on hover, so status changes do not shift the folder browser.
- **Documentation file management:** Open in Explorer opens the current directory. Each file/folder's ⋯ menu and right-click menu offer Move to and Delete; the tree offers these actions too. Moves preserve registered folder IDs, descendant paths, and connections, and reject collisions or moving into a descendant. Confirmed deletion permanently removes contents and nested catalog records/connections. Catalog writes are guarded before touching files; failed saves restore the original paths and metadata. Cleanup runs in the background and reports the retained temporary location on failure. Read-only pages cannot modify files.
- **Portable shared applications:** the target descriptor introduced in catalog format 2 stores a target kind, executable/shortcut filename, portable folder hint, and optional installed-product identity. Current-user/Desktop/Start Menu paths resolve separately on each PC; shortcuts stay intact. Installed-app resolution uses local registration/hints and never scans drives. Missing or ambiguous apps offer the existing local Locate action. Personal application paths remain local, and raw arguments are preserved. Version-1/2/3 catalogs upgrade with exact recovery backups; older writers reject the current format 4.
- **Inline documentation files:** the same browser lists actual files and subfolders, with file type/size, Open/double-click, New folder, Add files, Refresh, Up, and clickable breadcrumbs. Registered documentation entries can be files or folders retaining their IDs and connections. The former Files in this folder button and modal file browser are replaced by direct inline access. Search reads real files/folders recursively in the background; stale navigation results are discarded, failed refreshes retain the displayed listing, and copies keep originals while rejecting duplicate names. Navigation, catalog switching, and closing administration are blocked during an active copy.
- **License row actions:** Manage licenses reserves its measured text width plus table padding, so the label fits at the compact window size.

- **Admin Settings:** create a portable team configuration beside a new catalog in a shared network/UNC folder, or open the same configuration on another admin PC. Creation copies the current inventories, documentation defaults, and stable IDs without moving the original catalog or sharing personal entries/license keys. Each PC remembers only its selected configuration path locally. Documentation location/root controls now live in Settings; selecting a new location keeps existing files in place and requires existing documentation folders to be present there.
- **Shared admin saves:** atomic JSON publication, a shared lock, and revision checking reject stale edits instead of overwriting another admin's work. Admin windows check for changes every 5 seconds in the background, pausing while an editor, documentation window, unsaved catalog change, or settings draft is open. Settings offers Reload catalog and Retry saving; rejected drafts stay in memory and can be exported with Data tools. Missing/unavailable team files never become an empty catalog. Startup offers Retry or Choose team configuration for recovery. Use the same live network files and this app version on every admin PC; cloud-synced copies and older writers do not participate in this coordination.

- Main screens open maximized on a fresh profile and share the user's latest size, position, and maximized state across navigation and restarts. Editors/management dialogs initially follow the parent and remember their own placement by dialog type; small confirmations and system pickers stay compact. Display preferences are local and separate from catalog/workplace backups.

- **Admin related entries:** add/edit forms and documentation row controls offer Related entries → Choose entries. Each checked entry creates a direct two-way connection. Shared documentation can link to Contacts and Outlook independently. Selecting an item selects only that item; editing its connections preserves every other pair. Use selection stages the draft until the owning item is saved. Row counts/menus show direct connections; renames preserve IDs and deletion removes only links touching the deleted record. Catalog format 4 protects this behavior from older group-expanding writers. Existing saved links are retained during upgrade; uncheck old unwanted links once. The relationship UI remains admin-only.

- Original architectural artwork inspired by dark timber, shoji screens, and warm lantern light.
- Readable dark theme with 14px body text, brighter secondary labels and input hints, larger card details, and less letter spacing in small headings.
- Scalable bookshelf mark, artwork, and icons drawn with QPainter; no external images.
- Focus and hover states, password visibility toggle, and keyboard navigation.
- Gentle entrance animation; pass `animate=False` to disable it.
- Compact single-panel layout below 900px, with scrolling for short windows.
- **Admin sign-in** opens the Administration window with a combined **Full library** tab and separate **Licenses**, **Applications**, **Phone apps**, and **Websites** tabs. **Back to welcome** returns to the welcome screen.
- **Full library** brings all four inventories into one searchable, read-only collection inside administration. It includes type filters, summary counts, and name/type sorting. Returning to the tab refreshes additions, edits, and removals from the other tabs. Its sort order is preserved independently of inventory-tab sorting.
- In **Phone apps**, choose **Add phone app** and enter just its name. No path, executable, URL, or phone connection is needed. This is an inventory of the apps you have, with search, name/recent sorting, editing (or double-click), and removal after confirmation. Cancelling keeps the list unchanged; this list is separate from desktop applications.
- **Licenses** contains the item and license workflow. **Applications** and **Websites** each have their own independent list, search, sorting, and add/edit/remove controls.
- In **Applications**, choose **Add application**, then **Browse…** to select a Windows executable (`.exe`) or shortcut (`.lnk`), or paste its path. Its name is filled from the selected filename and can be changed. The icon preview and list use that file's Windows icon, including a shortcut's custom icon, with a generic file icon if Windows provides none. Missing paths, folders, and other file types are rejected. Paths with spaces, Unicode, surrounding quotes, or environment variables are supported.
- The **Launch target** field also accepts shortcut-style arguments, for example `"C:\Program Files\App\app.exe" -launch -reg` or `C:\Tools\app.exe --config "C:\Data Folder\settings.json"`. Quote the application path when it contains spaces and is followed by arguments. The portable shared target and raw arguments are stored separately, and the full target is shown in the list and restored when editing. Icons come from the file only. Browsing for a replacement file keeps existing arguments. These are still configuration entries, not live launching actions.
- Shared shortcuts are kept as portable `.lnk` references, rather than replaced with their target executable. Their arguments, working directory, and custom icon remain in the original shortcut for future launching. Selecting, editing, or adding an application never launches or modifies that file.
- Search applications by name or application path, or sort by name/recently added. **Edit** (or double-click) changes a name or file path and updates its icon. The trash icon removes a list entry after confirmation; the application or shortcut on disk is kept.
- In **Websites**, choose **Add website**, paste a **Website URL**, and optionally change the **Website name** suggested from the domain. Bare domains use HTTPS; HTTP, HTTPS, internal hosts, ports, paths, queries, and fragments are supported. Invalid addresses and other URL schemes are rejected. Entries use a local globe icon; adding or editing a website never visits it or downloads site data.
- Search websites by name or URL, and sort by name/recently added. **Edit** or double-click changes the selected entry while preserving its identity. The trash icon removes only that website entry after confirmation. Cancelling an add, edit, or removal keeps the list unchanged.
- Add an item with a name and optional category. Each item opens its own license subwindow; use **Manage licenses** or double-click an item to return to it.
- Inside **Manage licenses**, choose **Edit item** to change the item's name or category later. The item list, category filter, and subwindow update immediately; existing license entries, keys, and counts are preserved.
- The trash icon beside **Manage licenses** in the Licenses list deletes that item and all its license entries after confirmation. Cancelling keeps everything unchanged. The list, categories, and totals update immediately after deletion.
- Inside **Manage licenses**, each entry has a trash icon beside **Edit**. It removes only that license entry, including its key and counts, after confirmation. Other entries and the item are kept; available/used totals update immediately.
- **Manage licenses** opens an item's license subwindow. Choose **Add license entry**, enter a **License label**, and select a **Tracking type**: **Count only** or **Count + license key**. Set separate nonnegative **Available licenses** and **Used licenses** fields. Their sum is the total license pool. Keys are masked until you choose **Show key**.
- Each license row has quick **− / +** controls around its **Used** count. **+** moves one available license to used; **−** returns one used license to available. These actions preserve the pool total and stop at zero. Use **Edit** to adjust the pool counts directly or change a key.
- For **Count + license key** entries, enable **Unlimited uses** to display **∞** available and **—** used. Count controls are hidden and usage is not tracked for that key. Edit the entry to switch unlimited uses off again; its previous finite counts are retained. Switching to **Count only** also switches unlimited uses off.
- Items containing an unlimited key show **∞** available. If every entry is unlimited, Used is **—**; if limited and unlimited entries are mixed, Used shows only the limited entries' usage and is labelled **tracked**.
- The subwindow and item list show combined available and used counts immediately. The item list supports search, category filtering, and sorting. Usage is recorded as a count; individual users or assignments are not tracked.
- Admin application and website changes save automatically to a shared JSON catalog. Each Windows user's Collection selections and personal apps/websites save in a separate config file. Phone apps and license metadata/counts now persist, while key values remain in memory only; there is no admin authentication yet. See [STORAGE.md](STORAGE.md).
- **Open TSLibrary** opens a workplace with **Websites**, **Applications**, and **Collection** tabs. Collection shows the admin-managed apps and websites. Each card has its own **Add to workplace** / **Remove from workplace** button and selected check. The live **Selected** side list shows every chosen Collection entry, independently of search/type filters, and scrolls for longer selections. Remove a pick using its sidebar **×** button or **Delete** on a focused sidebar row. **Space** toggles a focused card. Removing a selection does not delete the admin record. Selected records follow admin name/target edits by stable ID. Deleted catalog records disappear from the workplace.
- Add personal apps and websites directly in their workplace tabs. Each card contains **Open website/application**; personal cards also contain **Edit**. These tabs have no bottom action bar or Remove controls. Manage Collection selections in Collection. **Space**, **Enter**, or double-click open a workplace entry; **F2** edits a focused personal entry. Opening uses the default browser or Windows file association. Executable/shortcut arguments are preserved; missing targets and launch failures are reported.
- The workplace supports search, name sorting, Collection type filtering, keyboard navigation, and responsive cards. **Refresh collection** reloads shared changes made in another app instance. Each tab retains its own search/sort state. **Back to welcome** allows returning to the admin sign-in flow.
- The separate read-only library remains available through `python main.py --library` and the admin **Full library** tab; it combines all four inventories from the shared session.
- The library has type totals, a responsive card grid, search across names and public details, an **All types** filter, and **Name: A to Z**, **Name: Z to A**, and **Type, then name** sorting. Search and type filters work together; **Clear filters** resets them while preserving the sort choice. **Ctrl+F** focuses search. Selecting a card shows its full public details in the footer and tooltip.
- Library cards are read-only inventory entries. They do not launch applications, visit websites, change license usage, or display license keys. Empty collections and searches with no matches have separate guidance. Use `python main.py --library` to open this view directly.
- Normal access requires no account. The username/password form is for admin access; there is no self-registration option.

- Everyday workplace additions include favorites/groups, compact list view, Ctrl+K quick launching, local missing-app repair, named launch sets, personal-entry removal, startup preferences, validated backup/restore, CSV exports, license owner/renewal details, and a standalone Windows installer. See README.md for the controls and remaining deferred items.
